# AI/LLM Integration Guide

## Purpose

TraineeAI converts desktop, browser, and optional RDP activity into structured JSONL artifacts. An AI or LLM should use these artifacts to describe a user's task, identify repeated workflows, or prepare a human review. It must not treat the logs as complete proof of user intent or task success.

The recommended integration point is `llm-payloads.jsonl`, generated by `analysis.analyze`. Each line is a self-contained prompt for one candidate task episode.

## Safety And Data Boundaries

- Process data only with the recorded user's informed consent.
- Keep raw `events.jsonl`, `browser-events.jsonl`, and `rdp-events.jsonl` local unless the user explicitly exports them.
- Do not send raw RDP input streams to a remote model by default. They can contain keyboard and mouse data that is unnecessary for task summarization.
- Redaction is best effort, not a guarantee. Reject, mask, or require review for credentials, tokens, personal data, payment data, private URLs, and source-code content before model upload.
- Never infer a password, a clipboard value, command output, a remote-screen state, or a successful remote action when the artifacts do not explicitly contain it.

## Data Flow

```text
Collectors
  -> desktop JSONL / browser JSONL / optional RDP JSONL
  -> python -m analysis.analyze
  -> timeline.jsonl + episodes.jsonl + llm-payloads.jsonl
  -> LLM task analysis
  -> human review or approved automation proposal
```

### Collector Sources

| Source | Typical events | What it establishes | Important limitation |
| --- | --- | --- | --- |
| Linux desktop | active window, accessible UI focus and selection | application and desktop context | text-change noise is intentionally suppressed |
| Windows desktop | foreground-window changes | application, window title, PID, executable | no control-level UI semantics |
| Browser CDP | navigation, click, input, submit, focus, keyboard | browser page and element context | web apps can duplicate input events |
| Windows RDP | raw keyboard/mouse input, submitted command buffer | local input directed at one selected `mstsc.exe` window | cannot confirm remote application state or command completion |

## Creating Artifacts

Run analysis after capture. Supply either desktop, browser, or both inputs.

```bash
python3 -m analysis.analyze \
  --desktop events.jsonl \
  --browser browser-events.jsonl \
  --output test-output/episodes.jsonl \
  --timeline-output test-output/timeline.jsonl \
  --llm-payload-output test-output/llm-payloads.jsonl
```

For a Windows RDP recording, use the RDP log as the desktop input:

```powershell
python -m analysis.analyze `
  --desktop rdp-events.jsonl `
  --output test-output\rdp-episodes.jsonl `
  --timeline-output test-output\rdp-timeline.jsonl `
  --llm-payload-output test-output\rdp-llm-payloads.jsonl
```

`analysis.analyze` performs these deterministic steps before an LLM is involved:

1. Parses JSONL collector records.
2. Normalizes browser and desktop formats into a unified event model.
3. Enriches browser events with the latest desktop window context.
4. Reduces known browser input noise and groups events into sessions and candidate episodes.
5. Writes one LLM payload per episode.

## Artifact Contracts

### `timeline.jsonl`

Each line is a normalized event. Relevant common fields are:

```json
{
  "timestamp": "2026-09-01T12:00:00.000000Z",
  "source": "browser",
  "event_type": "click",
  "app_name": "chrome.exe",
  "window_title": "Example - Chromium",
  "url": "https://example.test/",
  "target": {"role": "button", "text": "Submit"},
  "data": {},
  "entities": []
}
```

Treat `source`, `event_type`, `app_name`, `window_title`, `url`, `target`, `data`, and `entities` as evidence. Fields may be absent. `raw` source records are deliberately omitted from the serialized timeline.

### `episodes.jsonl`

Each line is a candidate episode, not a confirmed task:

```json
{
  "episode_id": "ep-00001",
  "start": "2026-09-01T12:00:00Z",
  "end": "2026-09-01T12:01:00Z",
  "duration_sec": 60.0,
  "applications": ["chrome.exe"],
  "entities": [],
  "actions": [
    {"timestamp": "...", "source": "browser", "app": "chrome.exe", "type": "click"}
  ]
}
```

An episode can contain unrelated actions when the system has insufficient context to split them. The model must lower confidence rather than inventing a relationship.

### `llm-payloads.jsonl`

Each line contains:

- `system_prompt`: TraineeAI's grounding instructions.
- `user_prompt`: a JSON representation of one candidate episode.
- `output_schema`: required response fields.

Use one payload per model request. Do not concatenate unrelated episodes into one prompt unless the application deliberately performs a second-stage aggregation with explicit provenance.

## Recommended LLM Behavior

The model should return only the schema supplied in `output_schema`:

```json
{
  "intent": "string",
  "goal": "string",
  "steps": ["string"],
  "inputs": ["object"],
  "outputs": ["string"],
  "parameters": ["object"],
  "success_criteria": ["string"],
  "applications": ["string"],
  "evidence": ["string"],
  "confidence": 0.0
}
```

Apply these rules in addition to the generated system prompt:

1. Describe only actions supported by events.
2. Distinguish an observed action from an inferred goal. Use uncertainty in `evidence` and lower `confidence` when intent is ambiguous.
3. Preserve redaction markers such as `<REDACTED>` and `<REDACTED_COMMAND>`; never replace them with guesses.
4. Treat `rdp.command_submitted` as an attempted local submission, not proof that the command executed remotely.
5. Treat browser navigation as evidence that a page loaded, not proof that a business action succeeded.
6. Ignore or summarize raw keyboard, focus, and mouse-move noise unless it changes the meaning of the workflow.
7. Do not propose replay or automation steps without an explicit human approval stage.

## RDP-Specific Guidance

RDP recordings are useful for reconstructing a local interaction sequence and submitted command text. They do not inspect the remote display or receive remote process status.

- `rdp.input` represents a physical local input event while the selected `mstsc.exe` window was foreground.
- `rdp.command_submitted` is emitted after Enter from the local command buffer. Its `terminal.shell` value is user-configured as `powershell`, `bash`, or `unknown`; it is not automatically detected.
- `rdp.paste_detected` confirms a paste gesture but intentionally omits clipboard contents.
- `rdp.recording_paused`, `rdp.recording_resumed`, and `rdp.recording_stopped` are user-control events, not remote actions.

For RDP summaries, use language such as "the user submitted a command in the selected RDP session" rather than "the remote server executed the command." See [RDP recorder requirements](rdp-recorder-requirements.md) for the full boundary.

## Example Integration

The following pseudocode reads each prepared payload and sends it to an LLM provider selected by the host application:

```python
import json
from pathlib import Path

for line in Path("test-output/llm-payloads.jsonl").read_text(encoding="utf-8").splitlines():
    payload = json.loads(line)
    # Review or apply local policy checks before this boundary.
    result = llm_client.generate(
        system=payload["system_prompt"],
        user=payload["user_prompt"],
        response_schema=payload["output_schema"],
    )
    store_for_human_review(result)
```

The host application is responsible for authentication, transport encryption, provider selection, retention, user consent, rate limits, and validation of the model response. TraineeAI does not make a network request to an LLM.

## Human Review And Automation

Treat model output as a draft workflow description. Before exporting a workflow or replaying an RDP scenario, require a reviewer to confirm:

- the intended target environment;
- redaction and data-sharing policy compliance;
- every proposed action and parameter;
- checkpoints and stop conditions;
- whether the scenario contains a paste marker or unsupported action.

RDP replay remains dry-run unless the user explicitly passes `--execute` to the replay launcher. Do not let LLM output enable replay automatically.

## Troubleshooting

- Empty `llm-payloads.jsonl`: confirm at least one collector log is non-empty and inspect collector diagnostic logs.
- Too many browser events: rely on `timeline.jsonl` and `episodes.jsonl`, not the raw browser log.
- Ambiguous episode: preserve ambiguity and request human context; do not merge it with adjacent episodes automatically.
- RDP command missing: commands inserted from clipboard are intentionally not captured, and the local collector cannot determine whether the remote surface was a terminal.
- RDP replay rejected: focus the selected `mstsc` window and match the recorded client size, or consciously use the explicit geometry override.
